# SM75 experimental prerelease — v0.1.0

This is an unofficial, experimental NVIDIA Turing (SM75) fork of the Dao-AILab FlashAttention codebase, primarily tested on two RTX 2080 Ti GPUs. It is not an official release by Dao-AILab or NVIDIA. It does not publish to PyPI.

## Installation

Use the GitHub release wheel that matches your Linux Python, PyTorch CUDA version and C++ ABI, then install with `pip install --no-deps <wheel-file>`. You must have compatible PyTorch and `einops` already installed. Source builds default to SM75-only using `pip wheel . --no-build-isolation --no-deps`, with the CUTLASS Git submodule initialized.

## Features and limits

- FlashAttention-2-style Python imports/API, native SM75 FP16 forward attention, dense/packed/variable-length and contiguous/paged KV-cache paths, no SDPA/xFormers runtime fallback for tested valid SM75 routes.
- Tested head dimensions: 32, 64, 80, 96, 112, 128, 160, 192, 224, 256, subject to the documented option/shape restrictions.
- BF16 input is computed as FP16 and output converted back to BF16; true BF16 native compute is not provided on Turing.
- Dropout is intentionally unsupported; backward is experimental and only tested at dropout=0. This is inference-first, not a certified training backend.
- GPU compatibility beyond RTX 2080 Ti, Windows builds, and general all-model interoperability have not been independently validated.

## Measured evidence — historical baseline

The original July 13, 2026 installed-wheel release candidate was commit `3bc7933`, with PyTorch `2.6.0+cu124`, Python 3.10.12, NVCC 12.5, on RTX 2080 Ti. Exact JSON outputs are preserved in `historical/`.

| Workload | Rows | Geomean speedup vs reference | Minimum speedup |
| --- | ---: | ---: | ---: |
| Attention operations | 22 | 1.723x | 1.144x |
| KV-cache update/decode operations | 11 | 2.894x | 1.184x |
| Installed-wheel Transformers generation | 20 | 1.100x | 0.963x |

These are *public-operation pipeline* results, not pure CUDA-kernel head-to-head measurements. The references include SDPA plus head expansion and other preprocessing; see the main README. The generation memory maxima in that old harness were artificially inflated by the second model remaining alongside the first. They must not be used to claim higher GPU memory demand. Any new wheel is a distinct revision and these historical numbers are not its measurements.

## Validation and traceability

Use `make sm75-ci-quick` for a fast CUDA integration run and `make sm75-release-audit` for a GPU release audit. Record the release tag/commit, `sha256sum`, exact wheel filename, Python/Torch/CUDA/compiler versions, and actual passed test counts in the GitHub release description. Raw JSON and large logs can be attached to the release.
